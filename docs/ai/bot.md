# 钓鱼 Bot 说明

本文档定义当前 Bot 产品状态、架构边界和验收标准。

玩法规则以 [`docs/rules/game-rules.md`](../rules/game-rules.md) 为唯一权威来源。本文档不能修改或补充玩法；代码、测试或注释与规则文档冲突时，以规则文档为准。

## 1. 当前状态

- Godot 本地单机版当前只有一种正式对手：`LegacyGeneBot`。
- 游戏只选择 Bot 数量，不提供 Bot 难度选择。
- `LegacyGeneBot` 使用已经冻结的遗传参数，运行期间不会训练或变化。
- `RandomBot` 只用于自动测试和基线比较，不出现在正式界面。
- 搜索、CFR、自我对战和机器学习路线均未确定，不属于当前实现范围。

## 2. Bot 阵容

| Bot | 当前用途 | 是否训练 | 是否出现在游戏中 |
| --- | --- | --- | --- |
| `LegacyGeneBot` | 当前正式对手 | 参数曾离线遗传优化 | 是 |
| `RandomBot` | 合法动作与强度基线测试 | 否 | 否 |
| `BotPolicy` | GeneBot 优化器的固定启发式基线 | 否 | 否 |

未来若决定引入新 Bot，必须先在本文档中明确其信息边界、数据来源、训练方式、运行成本和验收标准，再开始实现。

## 3. LegacyGeneBot

`LegacyGeneBot` 是当前唯一正式 Bot。它可以使用自己的手牌、公开筹码、底池、座位和公开行动历史，但不能读取对手隐藏手牌或剩余牌堆。

当前 Godot 游戏使用以下冻结参数：

```text
entry_conf   = 0.32674856916965
counter_conf = 0.776025883972883
greed        = 1.45151789486408
bluff        = 0.00786754488945007
```

这组参数只控制入局判断、再次投入判断、下注尺度和少量随机行为。它不在游戏运行期间更新，也不代表未来 AI 方向。

### 3.1 优化记录

Godot 离线优化器使用固定种子，让候选参数对战 `RandomBot`、`BotPolicy` 和冻结参数基线，覆盖 2 人、4 人和 6 人局。训练、验证和最终测试使用互不重叠的种子。

冻结参数在 300 场最终测试中的记录为：

| 指标 | 当前参数 |
| --- | ---: |
| 归一化筹码分 | +0.3276 |
| 平均持有筹码 | 197.177 |
| 整场胜率 | 16.3% |
| 淘汰率 | 4.3% |
| 存活率 | 95.7% |

该结果只描述当前参数在固定评测环境中的表现，不能证明全局最优，也不能代表真人对战强度。

可复现命令：

```bash
godot --headless --path godot_client --script res://tools/optimize_gene_bot.gd
```

## 4. RandomBot

`RandomBot` 只从规则层给出的合法动作中随机选择，不自行修改合法动作范围。

第一次行动时，先在弃牌和下注两类动作中随机选择；选择下注后，再从合法金额中随机选择。已经下注后，在过牌和带之间随机选择；不能带时只能过牌。

不要把每个下注金额与弃牌直接放进同一个等概率数组，否则底池越大，随机 Bot 越倾向下注，基线会被金额数量扭曲。

## 5. 统一接口

所有当前和未来 Bot 都必须通过同一契约读取状态并提交动作：

```text
BotContext
  observation
    actor_seat
    own_cards
    own_hand_result
    pot
    public_seats
    active_seat
    round_index
    structured_action_history
  legal_actions
  decision_seed
```

公开座位信息只能包含筹码、参与状态、弃牌状态和公开下注信息，不能包含其他玩家的 `cards` 或 `hand`。

Bot 返回：

```text
BotDecision
  action
  amount
```

最终动作必须由规则层再次校验。Bot 不能绕过 `LocalGame` 直接修改筹码、底池、行动顺序或结算结果。

## 6. 保留的基础设施

以下能力不属于某一种 Bot，因此继续保留：

- `BotContract`：公开观察、结构化合法动作和决策校验。
- 结构化行动历史：不依赖中文日志解析。
- `RoundSimulator`：纯数据状态、深克隆、状态哈希和逐步执行。
- 固定随机种子：支持可复现测试和未来 Bot 比较。
- 模拟器与 `LocalGame` 的逐动作一致性测试。
- 隐藏信息边界测试。

这些基础设施可以服务于未来的规则测试、离线评测、自我对战或其他 AI 方向，但保留它们不表示项目已经选择搜索或机器学习路线。

## 7. 当前验收标准

1. `LegacyGeneBot` 只能读取自己的手牌和公开状态。
2. 所有返回动作必须通过当前合法动作集合校验。
3. 固定种子下的决策和整场测试必须可复现。
4. 2～6 人局能够连续完成，不能出现非法动作或筹码不守恒。
5. Godot UI 不显示不存在的 Bot 难度或搜索状态。
6. 玩法、测试和实现必须与 [`docs/rules/game-rules.md`](../rules/game-rules.md) 一致。

## 8. 未来方向

项目的长期目标是通过学习与训练得到真正强力、能够稳定与人类玩家对局的 AI Bot。下一种 Bot 的具体技术路线尚未决定，候选方向包括真人数据驱动的对手模型、自我对战策略、CFR 类信息集求解或其他机器学习方法。

作出决定前，需要先回答：

- 是否使用真实玩家数据；
- 是否允许自我对战训练；
- 是否要求策略与 Legacy 完全独立；
- 目标是平均筹码、整场胜率还是特定真人体验；
- 如何建立训练、验证和最终测试的隔离数据集；
- 运行时 CPU、延迟和安装包大小预算是多少。

在这些问题确认前，当前正式产品保持 `LegacyGeneBot` 单一对手。
